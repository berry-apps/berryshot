# Fix: SHA256 hash computed before notarization modifies DMG

## Root Cause

In `build_app.sh`, the SHA256 hash is computed on line 139, **before** `xcrun stapler staple` on line 156 modifies the DMG. The stapler embeds a notarization ticket into the DMG file, changing its content and therefore its hash.

**Current order** (broken):
1. Line 134: Create DMG
2. Line 139: Compute SHA256 ← hash of pre-notarization DMG
3. Line 142: Save hash to `.sha256` file
4. Line 156: `xcrun stapler staple` ← modifies DMG, hash now stale

**Correct order**:
1. Create DMG
2. Notarize + staple (modifies DMG)
3. Compute SHA256 ← hash of final DMG
4. Save hash

## Change

**File**: `build_app.sh`

Move the SHA256 hash generation block (lines 137-142) to after the notarization/staple block (after line 174, before the final success message).

## Verification

Run `./release.sh 1.1.1`, then:
```bash
shasum -a 256 landingpage/assets/BerryShot.dmg
cat landingpage/assets/BerryShot.dmg.sha256
```
Both should show the same hash.
